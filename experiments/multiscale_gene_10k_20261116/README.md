## 四组模型

| variant | 基因与空间尺度 | 字典 | 每图非零系数上限 |
| --- | --- | --- | ---: |
| single_vector | 256 个，16×16 | 64 维向量 | 1,024 |
| multiscale_vector | 96/80/80 个，16/32/64 分辨率 | 各尺度 64 维向量 | 512/256/256，合计 1,024 |
| multiscale_conv | 同上 | 各尺度 64×3×3 卷积模板 | 同上 |
| dense_ae | 单尺度普通 AE | 无稀疏字典 | 不适用 |

多尺度分支来自编码器中对应的 192、128、96 通道特征。每个分支先预测非负稀疏系数，再经共享字典相加得到 64 通道特征。粗尺度进入原解码器；中、细尺度的字典特征分别经线性 1×1 投影，在解码器对应分辨率的卷积之后、后续残差模块之前加入。所有进入 RGB 解码器的图像依赖信息均经过字典，无原图或未稀疏编码的旁路。

表达式：`F_s = sum_k dictionary_{s,k} * activation_{s,k}`，`RGB = nonlinear_decoder(F_coarse, F_medium, F_fine)`。向量字典使用逐点求和，卷积字典使用一致的 PyTorch cross-correlation 方向，并支持逐基因贡献与删除。

特征合成严格线性，RGB 解码非线性。因此单个基因删除产生的 RGB 差值可以观察，但单独 RGB 解码图不要求相加等于整图。基因激活不是对象或实例分割。

### 稀疏预算的实现选择

原模型为每个 16×16 位置 Top-4，每图至多 1,024 个正系数。多尺度若仍每个位置 Top-4，会大幅扩大总信息预算。因此本试验统一采用“每图、每尺度，将通道和空间展平后正值 Top-k”；单尺度也使用相同的全局 Top-k 原则，合计预算统一为 1,024。

这是相对于旧百万模型的显式变化。它能控制激活数，却可能让激活集中于少数位置，不应声称等同于旧版每位置竞争。多尺度预算先设 512/256/256，不表示最优尺度分配；实际激活和空间使用会记录。当前模型不加入额外基因使用率均衡或基因复活损失。

三组稀疏模型共享总基因数和最大非零系数数。参数量、空间系数槽位数及前向卷积/字典 MACs 同时记录；多尺度空间位置的索引开销更大，等激活数不等于等比特率。卷积模型字典参数更多，效果提升也不能全部归因于空间归纳偏置。

## 训练与队列

- GPU 上限 4 张 L20，每模型两张卡 NCCL DDP，优先同时训练两个新多尺度模型。
- 其后自动训练相同数据上的 single_vector 和 dense_ae 对照。
- 每模型有效全局 batch 1,024 = 2 张卡 × 每卡 microbatch 128 × 累积 4 次。最初为每卡 64、累积 8 次；经真实训练 batch profiling 后扩大，保留训练进度和优化器状态。
- 每模型 1,000,000 张次，约 100 遍 10k 训练集；共 977 次更新，最后一批为 576 张，曝光预算不丢弃尾部。
- AdamW；学习率 2e-4 → 2e-5，前 25 步 warmup；梯度裁剪 1.0；BF16 可用时启用。
- 损失沿用 L1 + 0.1 LPIPS(AlexNet)，0.1 为控制设置，并非已调优最优值。
- 第 0、25、100、200……步验证；每 50 步和每次验证保存恢复检查点；每 5 步记日志。
- GPU 不可用时等待；不在 CPU 上训练或运行模型。

### 实测 batch 大小

用户要求检查 batch 是否饱和后，于第 41 步（向量）和第 32 步（卷积）保存暂停，使用真实街景、完整 L1+LPIPS、双卡 DDP 及全局 batch 1,024 测量三个 microbatch。每个设置先 warmup 一次，再测量三次，以中位数统计；取图批次预先准备，因此吞吐只包含批次已准备后的训练更新，不等于包含读取和验证的全流程速度。

| 每卡 microbatch | 向量模型峰值分配 / 保留显存 | 卷积模型峰值分配 / 保留显存 | 向量 / 卷积训练吞吐，张每秒 |
| ---: | ---: | ---: | ---: |
| 64 | 14.15 / 15.39 GB | 14.08 / 15.74 GB | 378 / 382 |
| 128 | 28.15 / 30.69 GB | 28.02 / 31.37 GB | 372 / 374 |
| 192 | 42.15 / 45.96 GB | 41.97 / 47.05 GB | 367 / 370 |

表中 GB 为十进制。更大的 microbatch 没有带来明显吞吐提升。128 是用户要求扩大 batch 后采用的折中；192 几乎填满保留显存，256 的预测需求超过可用显存，因此未尝试。保持有效全局 batch、累计曝光、AdamW 状态、学习率计划及采样流不变。192 设置的每卡 512 张分成 192/192/128，使用按实际图片数加权的累积；额外通过 3/3/1 的不等长累积梯度与整批梯度对照。该数值检查关闭 TF32，避免硬 TopK 的临界激活因不同 batch 形状的卷积舍入而改变。

原始记录、配置及执行代码变更前快照位于 `reports/batch_tuning/`；最终选择见 `selection.json`。只允许 microbatch 改变的恢复兼容检查已加入，修改数据、模型、有效全局 batch 或训练计划仍会拒绝恢复。
