# UrbanGene：整张街景编码相加的融合 Autoencoder 实验方案

日期：2026-11-15（北京时间）  
状态：方案草案，未启动训练。

2026-11-15 更新：用户进一步将目标明确为“从一组图片分解出共享变量，通过变量相加重建各张图片”。当前研究主线已改为 [数据集共享的可加视觉基因分解](DATASET_SHARED_ADDITIVE_GENE_EXPERIMENT_20261115.md)。本文件保留为此前整图融合方案的历史记录。

## 1. 本次确定的研究方向

用户明确选择：**两张完整街景的编码相加，能够生成融合后的街景。**

主任务改为：

\[
z_A=E_\theta(A),\quad z_B=E_\theta(B),\qquad
\hat C=D_\omega(z_A+z_B).
\]

其中，E重新参与图像任务训练，D为共享的非线性图像解码器。输入是两张完整街景；主模型不需要先发现实例、手选Slot或匹配语义类别。

本文对“融合”的工作定义：保留两张输入中的主要景观内容，在统一画面中形成合理街景。这个定义需要由数据构造规则进一步落地；单凭A/B无法唯一确定目标C。具体采用像素融合、物理场景合并还是教师生成的融合，应在训练前固定，不能在评价后混用。

建议核心研究问题：

> 能否通过联合训练图像编码器和解码器，使完整街景编码的简单相加成为一种有效融合操作，在保持图像质量的同时，保留双方内容并泛化到未见图像组合？

新的贡献顺序：整图编码可解码地相加 → 融合保真与自然度 → 未见组合泛化。共享离散Gene、物体实例发现与最小编码不是本轮直接成立的结论。

## 2. 核心变化

| 项目 | 原实验 | 新实验 |
|---|---|---|
| 输入表示 | 冻结DINO特征，再用Slot压缩 | 从RGB训练可更新的整图编码器 |
| 基本代码 | 32个带几何的连续Slot | 每张图一个完整场景latent，允许是空间张量 |
| 核心组合 | 编辑或替换某个Slot | 两张整图代码逐元素相加 |
| RGB监督 | 后训练一个Slot→VAE bridge | 从一开始训练图像解码路径 |
| 组合监督 | 先以单图特征重建为主 | 单图重建 + 明确定义的融合重建 |
| 主要证据 | 分组、重建、实例编辑 | 双方内容保留、融合自然度、未见配对 |

旧DINO+Slot结果作为历史诊断保留。冻结DINO缓存不适合作为新可训练编码器的固定输入，训练应重新读取RGB。

## 3. 先区分两个不同的“可加性”要求

### 3.1 主要求：相加后能够解码成融合图

\[
D(E(A)+E(B))\approx C.
\]

这是用户当前明确要求的可加接口。通过融合图目标直接训练，编码器与解码器可以共同适应这个接口。

### 3.2 更强要求：融合图自身的编码也等于两个代码之和

\[
E(C)\approx E(A)+E(B).
\]

更强要求不由上一条自动推出，也不一定与选择的融合规则兼容。

例如，如果希望A与自身融合仍是A，即C(A,A)=A，同时强制严格编码等式，则有E(A)=2E(A)，只能得到零编码。此时应使用可解码的加法接口，或改变定义为平均/显式输入数量等条件，不能一边要求幂等融合、一边强制严格latent加法。

如果任务定义为物理场景多重集合合并，A+A意味着增加一份对象，此时可测试计数式加法；但它已具有不同于“同图融合不变”的语义。

**建议首版采用3.1，把3.2作为需验证兼容性后才加入的消融。**

## 4. 融合算子决定数据与结论

### 4.1 加法接口的固有约束

\[
E(A)+E(B)=E(B)+E(A).
\]

因此同一个确定性解码器的输出对输入顺序不敏感。主任务应使用对称融合规则。如果要求“A作背景、把B放进去”，交换A/B又要不同结果，就需要角色编码、条件或其他算子；纯相加无法保留来源角色。

加法也会丢失来源归属，一份和向量不保证可唯一还原A/B。单张融合图容量有限，不能默认完整保存两张图的所有细节。

首版可采用如下任务契约：

- 融合规则对A/B对称。
- 两张图均必须影响输出，不能退化为始终选其中一张。
- 主体内容保留以预定义可测属性为准，不要求复制全部输入像素。
- 背景、透视、颜色与照明的冲突处理由数据生成规则明确规定。
- 输出画布尺寸固定；拥挤场景是独立难度条件。
- A+A的目标行为必须在训练前选择：同图保持不变，或增加一份内容。

### 4.2 三类数据方案及其能力边界

| 方案 | 怎样得到(A,B,C) | 可支持的结论 |
|---|---|---|
| 像素融合 | C=αA+(1−α)B等已知操作 | 编码加法能实现像素混合，不足以证明自然街景融合 |
| 可控场景合并 | 用已知场景规则分别渲染A、B和合并后的C | 可确证内容保留、计数和布局组合；需另测真实街景迁移 |
| 真实照片的融合目标 | 配对采集/编辑，或用图像生成器产生C并筛查 | 可训练真实照片融合，但目标规则、人工或教师信息必须披露 |

这三种任务不能互相替代。简单裁剪拼接和MixUp可以作诊断或基线，不能以它们成功为证据声称学会自然场景融合。

现有百万张无配对街景可用于AE预训练，但没有已验证的真实融合目标C。需要单独建立融合训练集，这是新路线的关键数据依赖。

### 4.3 推荐的数据推进方式

1. 在真实街景上训练AE，先保留图像质量。
2. 建立可控组合基准，给出严格的融合语义和独立C，验证整图代码相加能否完成明确任务。
3. 构建规模较小、质量经过检查的真实照片融合三元组，检验向真实街景的迁移。

可控基准中的A和B均为完整场景图。场景构造可以内部使用对象与布局，但模型训练只读取RGB三元组，不输入实例Mask、类别或Slot标签。它属于**配对组合监督**，不是仅靠无配对原图的无监督学习。

示例规则：在统一相机、光照与底图下，从两个不重复的可见内容集合分别渲染A、B，按固定的场景合并规则渲染C。对同一位置发生冲突、相机不同、物体重叠等情况，先排除，随后作为单独难度组。若对象身份用于训练/测试划分，仅用于数据构造，不把它提供给编码器。

公共背景在C只出现一次，而在A/B编码中出现两次，这是模型必须学会处理的因素；应单独评价，不能把忽略背景信息的行为当作普通可加性的普遍证明。

真实照片若采用教师模型生成C，则记录教师版本、提示、种子、筛查标准和拒绝率。模型表现上限受教师影响；评价应使用独立来源的目标、独立内容检查和盲评，不能只复用同一教师给自己的学生评分。若无法准备可信C，则只能报告未配对融合的探索结果，不能报告确定的融合准确率。

## 5. 首版模型

```text
完整街景A → 共享可训练编码器E → zA ─┐
                                       ├→ 逐元素相加 → 共享解码器D → 融合街景Ĉ
完整街景B → 共享可训练编码器E → zB ─┘

单图重建：I → 同一个E → zI → 同一个D → Î
```

建议首版使用确定性AE：

- 图像先统一为256×256，验证后扩到448×448。
- 编码器为残差卷积或层级视觉编码器，全部参数接受RGB训练梯度。
- 每张图一个空间latent，起点为8×32×32。它仍是整图代码，三维形状用于保留位置，不代表8个对象或32个Slot。
- A/B使用同一个编码器；latent形状一致，按相同位置和通道相加。
- 解码器为非线性上采样网络，可以配置少量空间注意力，以处理全局布局。
- 单图和融合共用解码器；首版不额外传入A/B原图、来源角色或单独的未相加代码。
- 禁止输入图像、编码器多尺度特征等跳连绕过加法瓶颈。
- 可用已有AE权重初始化，但需验证结构兼容；随机初始化与预训练初始化分开报告。

编码器“重新训练”首先表示参数参与优化，不等于必须随机初始化。DINO可以作为额外初始化/评价对照，但不再强制通过冻结DINO特征训练。

### 数值尺度

加法后的latent可能偏离单图分布，因此单图和加法输入必须在训练中共同出现。记录zA、zB及其和的均值、方差、范数和相似度，检测一方范数过大而主导融合。

原始求和为主接口。平均、输入数条件或归一化作为单列消融，不默默改写成另一个操作。固定两输入时，求和与平均只差常数尺度，该常数通常可被网络吸收，不能把“求和胜过平均”作为主要科学贡献。

需要不同数量输入时，必须明确额外测试范围；两个输入上的成功不自动推广到三个以上。

## 6. 损失函数

### 6.1 单图重建

\[
\hat I=D(E(I)),\qquad
\mathcal L_{\rm rec}=d(\hat I,I).
\]

首版距离：

\[
d(X,Y)=\|X-Y\|_1+\lambda_p\operatorname{LPIPS}(X,Y).
\]

建议λp从0.1开始，记录像素及LPIPS输入尺度；只用预设验证集调整。

### 6.2 融合重建是核心新增约束

\[
\hat C=D(E(A)+E(B)),\qquad
\mathcal L_{\rm fuse}=d(\hat C,C).
\]

\[
\mathcal L=\mathcal L_{\rm rec}+\lambda_f\mathcal L_{\rm fuse}.
\]

λf初值1，普通重建与融合样本起始各占一半训练任务。计入实际源图曝光次数，不能只按更新数比较预算。

保留单图重建以防模型放弃输入保真，只输出某种一般街景。融合目标则阻止模型只会重建、对相加latent毫无训练。

### 6.3 更强的latent加法损失：可选，不是默认

仅在数据融合规则与它兼容时考虑：

\[
\mathcal L_{\rm latent}=\|E(C)-E(A)-E(B)\|_1.
\]

需同步检查零编码、latent缩小、解码器放大、背景重复及A+A冲突。不能仅以该项下降宣称表示变得可加。

对于同背景、增加不同成分的场景，更合理的诊断可能是：

\[
E(C)\approx E(A)+E(B)-E(I_0),
\]

但这是背景校正的另一种规则，需要额外公共底图I0。它可作诊断，不能偷偷取代主接口D(E(A)+E(B))。也可以研究以某个公共底图为零点的编码，但其跨背景适用性必须另外验证。

### 6.4 质量增强的顺序

先只用像素/感知重建和融合损失验证机制。只有在AE本身清晰、融合任务仍显著模糊且目标质量可靠时，再单独比较对抗损失或生成式解码器。逼真度改善不等于保留了双方输入，需要同步检查内容保真。

## 7. 分阶段实验

### S0：定义融合契约并准备数据

固定对称性、A+A行为、背景冲突、布局与目标C来源。保存三元组来源、构造参数与划分。

交付：融合规则文档、固定(A,B,C)示例、无泄漏的数据manifest、配对监督口径。此阶段未解决，不能将无配对街景直接当作融合监督数据。

### S1：在真实街景上训练普通AE

用现有训练集固定20,000张多城市真实照片起步，沿用4096张独立验证街景。直接从RGB训练E/D，先检查编码器能否保留图像细节。

输出：原图/重建、PSNR/SSIM/LPIPS、latent分布、损失曲线。AE不清晰时，先调整编码容量与优化；无需先引入Slot。

### S2：训练两输入编码相加

从同一S1检查点复制实验分支，混合单图重建与融合三元组训练。E/D都更新；保留同预算不加融合训练的对照。

受控基准起始目标可设为10k训练三元组、1k验证和2k测试；这是需要构建的数量，不代表现有数据。首先验证协议与数据质量，再根据泛化与学习曲线扩规模。

输出固定六项：A、B、目标C、D(E(A))、D(E(B))、D(E(A)+E(B))。同时展示像素混合基线与未训练融合的AE输出。

### S3：真实照片融合迁移

使用独立构建的真实三元组；教师伪目标与人工/配对目标分开报告。训练中继续混入真实单图重建，避免模型只适应受控渲染分布。

分别比较受控预训练后迁移、直接训练真实三元组以及仅普通AE的表现；数据预算与计算预算分别列明。

### S4：未见组合与输入数量泛化

至少划分两类测试：

1. 来源图在训练中出现过，但A/B配对未出现：评价配对泛化。
2. 两张来源图及其同全景/近重复图片均未出现：评价来源泛化。

进一步留出城市、布局组合和外观条件。相同源图出现在不同配对中仍可泄漏，应按源图/全景/城市先分组，再构造三元组。教师目标的提示或模板也需独立留出。

三输入和以上是扩展实验，使用明确的场景合并规则与目标；不以代数上可求和替代生成正确性的测试。

### S5：再讨论视觉基因

若整图代码相加成立，再研究代码的哪些方向/子空间可复用，或引入共享字典约束。无需把当前的整图代码强行解释成一棵树或一辆车；要形成Gene论点，应增加复用与信息预算实验。

## 8. 必需基线与最小消融

| 方法 | 作用 |
|---|---|
| 仅训练单图AE，测试时直接相加 | 检验普通重建是否足以自然产生融合能力 |
| 冻结S1编码器，仅训练解码器接收相加latent | 检验编码器是否必须重新学习 |
| E/D联合训练 + 融合目标（主方法） | 测量融合训练与编码器适配的收益 |
| 相同代码/解码器预算，采用可学习的对称融合模块 | 测量简单加法相对于更灵活组合器的质量代价 |
| 像素平均/简单拼接 | 检查模型是否只完成基础图像混合 |

主要比较从相同S1检查点出发，使用同一三元组和同一重建距离。控制代码容量、解码器参数、源图曝光次数与优化预算。冻结编码器与联合训练的结果都要报告。

可学习组合器需对A/B对称，例如对带共享投影的两个token集合做无来源角色的集合交互；若使用有序concat，则对两种顺序同时训练/评价，并说明差异。

更强latent加法损失、随机初始化、sum/mean与输入数量条件分别作为后续消融，不首轮全部集成。

## 9. 评价

### 9.1 单图重建能力

在固定真实验证集报告PSNR、SSIM、LPIPS，以及原图/重建对照。确认融合训练是否破坏普通重建。

### 9.2 有可信目标C时的融合保真

报告与C的PSNR/SSIM/LPIPS，并在可控基准上测量双方对象、属性、数量和布局是否保留。评价可以使用scene spec或独立标注，不能将这些标签暗中输入模型。

图像评价器或语义相似度必须使用不同于训练教师的独立来源，并结合人工盲评；单个全局相似度可能对只保留一方的结果仍给高分。

### 9.3 无唯一目标C时的评价

分别评估：图像自然度、A内容保留、B内容保留、结构冲突和重复背景。通过盲评或独立的属性/物体检索辅助评价，报告两方得分及较弱一方，不能只报平均值。

这属于任务定义下的偏好与内容保留评价，不具有唯一像素真值。若只有无配对自然图片，不能报告确定的融合准确率。

### 9.4 退化与因果检查

- 固定A，更换B，输出应发生与B相关的变化；再反向检查。
- 比较正确配对、错配代码、零代码、均值代码和仅A/仅B输出。
- 记录A/B latent范数及其比值，检测一方持续压过另一方。
- 检查模型是否输出常见街景、像素重影、或目标教师的固定模板。
- A+A按预定义融合规则测试；不使用互相矛盾的幂等与严格加法标准。
- A/B顺序一致性是求和结构自带的工程性质，不算学会组合的独立证据。

### 9.5 泛化与统计

seen-pair、新配对、新来源、新城市和不同拥挤度分开报告。主要对照至少3个随机种子，按来源场景进行bootstrap，避免同一源图参与多个配对导致样本被当作独立。

## 10. 实施预算与保存原则

起始256分辨率，两张物理GPU上全局有效batch64，显存不足通过microbatch与梯度累积调整。S1可先设30k更新预算、S2先设20k更新预算，实际停止依据固定验证曲线和退化诊断。它们是后续训练配置建议，本次未启动。

CPU用于数据准备、绘图和测试；模型训练保持GPU执行。新源代码、训练配置与输出采用独立目录，已有停止的主实验、NAS资源及检查点完整保留。

百万张街景用于后续扩规模。先扩大数据、还是提高分辨率，应由重建与融合失败类型决定；每次变更单独记录，不能把目标数据不足误判为训练图片数量不足。

## 11. 论文可以怎样表述

> 本研究学习一种支持整图编码相加的街景融合表示。共享编码器将两张完整街景映射到同形状的latent空间，逐元素求和后，由共享非线性解码器生成融合图像。我们联合优化单图重建与配对融合目标，并通过冻结编码器、无融合训练及可学习组合器等对照，检验简单加法能否保留双方内容、维持图像质量，并泛化到未见来源和未见图像配对。

建议标题：**Learning Additive Whole-Scene Codes for Street-View Fusion**。

可加接口是一个结构约束；论文贡献取决于它在有明确目标的融合任务中是否有效，以及相对于同预算基线的证据。仅看到两张latent相加后能输出一张自然图片，还不足以证明内容融合成功。
